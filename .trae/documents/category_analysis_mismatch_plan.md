# 类目分析商品数量不对等问题修复方案

## 问题分析

### 1. 现象
- 数据集总商品数：12件
- 类目分析页面显示转化陷阱分类下：41件（键盘11 + 蓝牙耳机10 + ...）

### 2. 根本原因
`/api/category-analysis` API 每次请求都重新加载数据并分类，没有使用缓存数据：

```python
# /api/category-analysis 每次调用都重新执行
df = load_data()
df = preprocess_data(df)
df, _, _ = classify_products(df)  # 重新分类
```

这导致：
1. 分类结果可能与缓存不一致
2. 可能存在数据重复或计数错误

### 3. 解决方案
修改 `/api/category-analysis` API，优先使用缓存数据或确保每次分类结果一致。

## 文件修改计划

### 1. 修改 `app.py` 中的 `/api/category-analysis` API
- 优先使用缓存中的数据
- 如果缓存中有分类统计，直接使用
- 或者确保分类结果与缓存一致

## 实施步骤

1. **第一步**：修改 `/api/category-analysis` API，使用缓存数据
2. **第二步**：测试验证类目分析页面数据与总商品数一致

## 风险评估

- **低风险**：修改仅涉及数据读取逻辑，不影响核心分类算法
- **回滚方案**：恢复原始代码即可回退

## 验证标准

1. 类目分析页面显示的商品数量不超过总商品数
2. 各分类下的商品数之和不超过总商品数
3. 百分比计算正确（基于实际分类数量）
